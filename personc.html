2. What's already done on my part

  • Solo experiment plan written (Proposal/bimochan.html) — scope, pipeline sketch, tooling, done/good/stretch bar.
  • Pilot pair list picked — 8 pairs across all 4 contrast types (aspirated/unaspirated, retroflex/dental, vowel length, sibilant).
  • Clip naming convention + folder scaffolding for all 8 pairs (Proposal/clips/<pair_id>/).
  • First pair (ब/भ, ba_bha) recorded — 10 clips in.
  • QC/normalize + feature extraction script built and run (Proposal/scripts/extract_features.py) — 16kHz mono, silence-trimmed, MFCC+delta, spectral centroid, duration, VOT proxy. Produces Proposal/artifacts/feature_manifest.csv.
  • Baseline Random Forest classifier built and run (Proposal/scripts/baseline_classifier.py) — leave-one-out on ba_bha: n=10, accuracy 0.30. Low as expected for 10 samples / 29 features; not meaningful until more clips + a proper forced-aligned feature set exist. Confirms the extract→train pipeline runs end to end.
  • Fuzzy c-means built and run (Proposal/scripts/fuzzy_classifier.py, scikit-fuzzy) — ba_bha: n=10, argmax-membership accuracy 0.70, FPC 0.55.
  • GPC built and run (Proposal/scripts/gpc_classifier.py, sklearn GaussianProcessClassifier — RBF kernel + Laplace approx, a dependency-light stand-in for GPflow at pilot scale) — ba_bha: n=10, leave-one-out accuracy 0.40, per-clip posterior_probability/posterior_variance written to Proposal/artifacts/gpc_predictions.csv in the schema §7 needs.
Honest read of the numbers: all three arms are running on only 10 clips of one pair, so none of accuracy 0.30/0.70/0.40 should be read as a real result yet — they demonstrate the pipeline works, not that GPC underperforms fuzzy c-means. The GPC posterior is stuck near 0.50 (maximal uncertainty) on every clip, which is the correct behavior for a GP that's never seen enough data to be confident — not a bug. This becomes meaningful once the other 7 pairs have clips.
