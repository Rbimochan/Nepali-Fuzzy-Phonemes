2. What's already done on my part

  • Solo experiment plan written (Proposal/bimochan.html) — scope, pipeline sketch, tooling, done/good/stretch bar.
  • Pilot pair list picked — 8 pairs across all 4 contrast types (aspirated/unaspirated, retroflex/dental, vowel length, sibilant).
  • Clip naming convention + folder scaffolding for all 8 pairs (Proposal/clips/<pair_id>/).
  • First pair (ब/भ, ba_bha) recorded — 10 clips in.
  • QC/normalize + feature extraction script built and run (Proposal/scripts/extract_features.py) — 16kHz mono, silence-trimmed, MFCC+delta, spectral centroid, duration, VOT proxy. Produces Proposal/artifacts/feature_manifest.csv.
  • Local Streamlit recording booth built (Proposal/scripts/recording_booth.py) — mic device picker with live waveform monitor, output-format control (fixed a real bug: the recorder library defaults to WebM, not WAV), per-take signal diagnostics (duration/peak level), a "remaining only" sidebar filter, and a review panel to play back/delete anything already saved. Runs at localhost:8501 so mic access works reliably (a published Claude Artifact can't get mic permission — confirmed, it's an iframe Permissions-Policy block).
  • All 8 pilot pairs recorded — 81 clips, ~10 per pair, 1 speaker. Fixed a real bug hit on this full run: silence-trimming (top_db=30) was over-aggressive on fast/short words and clipped away real speech (e.g. taar, mool — raw audio had a clear 65% peak signal, trimmed output was <0.2s); now falls back to the untrimmed clip if trimming would remove more than half the audio. Also made the MFCC delta computation robust to short clips instead of crashing on width=9 exceeding available frames.
  • Baseline Random Forest classifier (Proposal/scripts/baseline_classifier.py) — leave-one-out, all 8 pairs (n=10–11 each): accuracies 0.00–0.36. See table below.
  • Fuzzy c-means (Proposal/scripts/fuzzy_classifier.py, scikit-fuzzy) — all 8 pairs: accuracies 0.45–0.70.
  • GPC (Proposal/scripts/gpc_classifier.py, sklearn GaussianProcessClassifier — RBF kernel + Laplace approx, a dependency-light stand-in for GPflow at pilot scale) — all 8 pairs: accuracies 0.20–0.73. Per-clip posterior_probability/posterior_variance written to Proposal/artifacts/gpc_predictions.csv.

Honest read of the numbers: baseline is consistently at or below chance (0.50) and fuzzy c-means consistently above it across all 8 pairs — that pattern is suspicious, not reassuring. With n=10 and 1 speaker, leave-one-out variance is huge, and fuzzy c-means's unsupervised clustering can look artificially good if the two classes happen to separate on a feature unrelated to the actual phoneme contrast (e.g. by recording order or a subtle mic-level drift). Do not present these numbers as "fuzzy beats the baseline" without more speakers — that conclusion needs to survive a second speaker before it means anything. GPC still shows near-random performance on most pairs (posterior likely still uncertain at this sample size).
